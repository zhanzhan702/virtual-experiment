### 修复组件缩放时"向上飘走"（transform-origin 缺失）
- 现象：把浮层从 `fixed+top` 改为 `absolute+bottom:100%` 时，漏改了 `transform-origin`——原用户调好的版本是 `transform-origin: top center`(顶边固定)，改造后只留 `transform: scale(0.6)` 默认 `center` 原点。
- 根因：`bottom:100%` 把面板"布局底边"钉在画布顶边，但 `scale(0.6)` 默认以**中心**为原点，会把整块上抬 `0.2×面板高` → 底边脱离画布顶边、向上飘，与"下边界紧贴 canvas-stage 上边界"冲突。
- 修复：`.terminal-guide-overlay` 增加 `transform-origin: bottom center;`（底边为缩放原点 → 底边固定、面板向上收缩，不再上飘）。最低侵入、一处 CSS。

### 修复"挂完表必须刷新才能进入下一步"的 bug（根因：stepId ref 不随路由同步）

- 现象：计量小室挂表（步骤5）后页面无法自动进入划开关（步骤6），必须刷新页面才能继续。
- 根因：`HCabinetLocalView.vue` 中 `stepId = ref(route.query.stepId)` 仅在组件初始化时读一次，**`router.replace` 跳步后从不更新**。挂表提交用正确的步骤5 id 后自动跳步骤6，但 `stepId.value` 仍停留在步骤5 id；到步骤6提交时 `submitStep` 用的是已完成的步骤5 id → 后端拒绝/错乱 → 卡在步骤6。刷新时 URL 的 query.stepId 已正确，`onMounted` 重读后正常，故"刷新才行"。
- 修复：在 `currentStepOrder` 之后新增 `watch(() => route.query.stepId, id => { if (id) stepId.value = id })`，使 stepId 跟随路由 query 同步。这样每次跳步后 stepId 立即指向当前步骤，后续 submitStep/saveDraft/getStepDraft 都写到正确步骤，无需刷新即可连续推进 5→11。
- 说明：内存态 5→6 推进本身靠 `watch(props.stepOrder)` 在 canvas 内构建步骤6，机制正常；本修复解决的是跨步提交时 stepId 错位。终端小室（步骤13+）共用同一 handler 与 stepId，一并受益。
